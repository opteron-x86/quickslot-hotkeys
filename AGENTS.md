# Documentation

Write project documentation around current capabilities, configuration steps and observable outcomes. Use direct, affirmative descriptions.

Keep changelog entries focused on user-facing changes. Put investigation history, implementation decisions, test reports, requested revisions and rejected alternatives in issues and pull requests.

Describe visuals by what users see. Describe controls by their actions and settings. Include technical details when they help the reader build, configure, integrate or test the mod.

Review documentation edits for development-history narration and contrastive phrasing before publishing.
